# 拾光通讯录 · 手动测试清单

> 测试地址：<http://47.118.56.190:8080/>  
> 预览数据：12 位联系人、4 位收藏（匿名只读）  
> 演示账号：`demo2026` / `demo123456`（12 位联系人，可编辑）  
> 建议浏览器：Chrome / Edge，桌面窗口约 1440×960；移动端用开发者工具切 390×844。

## 0. 开始之前

- 打开页面后按 `Ctrl + F5` 强制刷新一次，避免旧缓存。
- 未登录时看到的是**只读预览**；点输入框、星标、编辑、导入、导出等操作会弹出登录/注册窗口。
- 用演示账号登录，或自己注册一个新账号（新账号是空通讯录）。
- 测试会修改数据。需要恢复演示数据时执行：
  ```bash
  cd /mnt/e/dsh/addressbook-assignment
  npm run seed
  ```
  该命令只重置 `user_id IS NULL` 的预览数据，不会删除账号和账号下的联系人。

## 6. 导入 Excel（25 分）

使用样例：`docs/samples/import-demo.xlsx`。在 demo 账号 12 位联系人的状态下，第一次选择「合并更新」：

| 结果 | 数量 |
|---|---:|
| 新增 | 2（贾谊、王通） |
| 更新 | 2（罗峰、徐欣） |
| 跳过 | 0 |
| 未导入 | 1（第 6 行，邮箱 `not-an-email` 格式错误） |
| 导入后总数 | 14 |

检查：

1. 结果弹窗显示「4 位联系人已写入通讯录」，统计卡片为 2/2/0/1。
2. 错误列表显示「第 6 行 错误示例：邮箱地址…无效」。
3. 关闭后左侧出现贾谊、王通；收藏数变成 5（贾谊是收藏）。
4. 打开贾谊，应看到 4 条联系方式（手机、邮箱、微信、地址）。

再导入同一文件：

| 模式 | 预期 |
|---|---|
| 合并更新 | 0 新增、4 更新、0 跳过、1 错误 |
| 跳过重复 | 0 新增、0 更新、4 跳过、1 错误 |

边界：

| # | 操作 | 预期结果 |
